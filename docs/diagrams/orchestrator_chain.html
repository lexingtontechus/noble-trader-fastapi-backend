Gaps & unwired processes

  1. dynamic_atr tier is a dead write. dynamic_tier_optimizer._compute_dynamic_atr writes 17 per-symbol picks into param_store every 15 min. No production code reads TIER_DYNAMIC_ATR — only tests/test_param_store.py. The pre-sweep ATR optimization never reaches the sweep.
  2. The ATR picker never runs on the light path. tiered_atr.dynamic_atr_pick is called only from heavy_sweep.py (live cron 6 17 * * * from nt_symbol.sweep_cron; code default 0 20 * * * — AGENTS.md still says 20:00). The light sweep (every 15 min) reads brick_params.yaml, which only the heavy sweep rewrites. Nuance: the light path does scale brick_size every tick via geometry_intraday_scale_mode: live (ATR-now / ATR-at-write) — but not the brick counts (sl_bricks/tp_bricks). So the stop/target shape refreshes daily; only its dollar size tracks ATR at 15 min.
  3. Two ATR mechanisms that never meet. atr_reopt (4h) patches feature_flags.yaml clamps; dynamic_tier_optimizer (15 min) writes param_store. The picker reads only the former. Same conceptual lever, two stores, one orphaned.
  4. geometry_incubation tier is write-only. 28 rows per run; TIER_GEOMETRY_INCUBATION has no reader. The module is imported only by heavy_sweep.py.
  5. Three of five tiers are shadow. dynamic_deadline_mode, regime_edge_mode, geometry_incubation_mode = shadow — computed and stamped, but none gate a signal. Only geometry_intraday_scale_mode and dynamic_atr_mode are live (the latter on the heavy path only).
  6. 9 modules have no importer. Offline/CLI by design: fp_eval, common_factor, reachability_decay, leverage_eval, calibration_quality_gate, timesfm_zmap*, portfolio_compare, paper_retroclose, regime_state_store*. (* = actually live via function-local import)
  7. First-passage is built but unwired. AGENTS.md says it replaces the HMM; first_passage.py is imported only by fp_eval.py (offline). It reaches no live gate.
