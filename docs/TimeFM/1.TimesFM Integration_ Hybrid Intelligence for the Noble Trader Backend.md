Integrating **Google's TimesFM** (Time-series Foundation Model) with the **Noble Trader FastAPI Backend** creates a "Hybrid Intelligence" architecture. This setup combines the **local statistical precision** of Hidden Markov Models (HMMs) and Renko patterns with the **global pattern-matching capabilities** of a foundation model 1, 2\.  
The following plan outlines how to integrate these two codebases into a production-grade signal pipeline.

### 1\. Integration Architecture: The "Inference Bridge"

Because TimesFM is a large-scale foundation model, it should be deployed as a standalone **Inference Service** (e.g., on a GPU-enabled Render instance or Vertex AI) to avoid overwhelming the resource-constrained FastAPI backend used for execution 3, 4\.

* **FastAPI Backend Role:** Acts as the **Orchestrator**. It fetches OHLCV data from HyperLiquid/Yahoo, sends payloads to TimesFM, and integrates the results into the **EV Engine** 5, 6\.  
* **TimesFM Role:** Acts as the **Foundational Prior**. It provides zero-shot forecasting probabilities that supplement the existing heuristic Markov transitions 6, 7\.

### 2\. Core Logic Updates

The integration requires updating three specific layers of the Noble system:

#### A. The EV Engine Blended Probability ($P\_{win}$)

The current $P\_{win}$ is a weighted blend of $P\_{regime}$ (40%), $P\_{imbalance}$ (30%), and $P\_{markov}$ (30%) 6\.

* **The Update:** Introduce $P\_{timesfm}$ as a fourth signal source or, more effectively, use it to **inform the Bayesian Prior**.  
* **Formula:** $P\_{win} \= w\_r P\_{regime} \+ w\_i P\_{imbalance} \+ w\_m (\\text{Bayesian Update using } P\_{timesfm} \\text{ as Prior})$ 8-10.

#### B. The Bayesian Updater

Currently, the **Bayesian Updater** uses a heuristic $P\_{markov}$ (e.g., 0.65 for bull, 0.50 for neutral) derived from the HMM regime label 11\.

* **The Update:** The BayesianUpdater class in src/lib/bayesian-updater.ts will replace these heuristics with the actual forecast confidence score from TimesFM 7, 12, 13\.

#### C. Redis State Persistence

The trading:config:{symbol} Hash in Redis will be expanded to include new foundation-model fields 13, 14:

* p\_timesfm: The raw forecast probability (0–1) from the latest foundation model run.  
* timesfm\_horizon: The forecast window (e.g., "12h") used for the current signal.

To initialize this integration, add the following to your environment and configuration:

2. **New API Endpoints:** Create GET /signal/foundation to allow the Frontend Dashboard to visualize the foundation model's conviction alongside HMM and L2 data 23, 24\.  
3. **Regime Shift Meta-Signal:** Use TimesFM to validate HMM regime shifts. If the HMM detects a shift (e.g., bull → bear) and TimesFM confirms it with high confidence, trigger the **Adverse Shift Auto-Close** immediately 25-27.

### Summary of Value Add

This integration solves the **Underestimation of Risk** problem noted in the Senior Quant research 28, 29\. While local HMMs can be blinded by 45 days of recent data, TimesFM provides "institutional grade" context by recognizing patterns found across decades of historical market data, leading to a more robust **Aggression Scale** and **Effective Kelly** sizing 10, 13, 30\.
