#### Why the T4 Plan is the Right Choice:

1. **Polling Frequency vs. Burst Speed:** The Noble system relies on a **15-minute heart-beat** 2, 9\. Since the A10G only provides 33 hours, you would run out of credits halfway through the month just maintaining the Light Regime Tier, even without running any Heavy Sweeps.  
2. **Model Requirements:** **TimesFM** is a foundation model, but for **inference-only** tasks on 1-hour or daily bars (OHLCV), the T4’s 16GB of VRAM and Tensor Cores are more than sufficient Conversation History. You do not need the A10G’s high-end throughput for periodic financial time-series forecasts.  
3. **The "BETA" Upgrade:** Moving to a T4 allows you to immediately upgrade your **"BETA" constraints** (moving from 45-day to 90-day lookbacks and expanding from 3 to 5 brick-size multipliers) without hitting the 130s deadline guard used on Supabase 5, 6\.

### 3\. Implementation Recommendations for Lightning AI

To stay within the 95-hour T4 budget while managing 28 symbols:

* **Implement "Auto-Stop":** Use Lightning AI’s SDK to ensure the "Studio" (the instance) enters a sleep state immediately after the 15-minute or 4-hour job completes.  
* **Vectorized Inference:** Do not call TimesFM 2,688 times a day individually. Update the light-regime/index.ts logic to fetch all 28 symbols' data first, then run a **single batched inference** through the GPU to minimize "Active" time 9, 10\.  
* **Shift-Aware Wakeups:** Use the **Regime Shift meta-signal** to trigger an "emergency" Heavy Sweep when a symbol's volatility state changes (e.g., low\_vol → high\_vol). This is now the primary mid-week heavy trigger, since scheduled heavy sweeps only run on weekends. Reduces unnecessary sweeps by \~30–40% 11, 12\.

**Summary Recommendation:** Use the **Lightning AI Pro Plan on a T4 instance**. It provides the \~50-hour runtime needed for 28 symbols with a comfortable 45-hour buffer for intensive backtesting and manual optimization 13, 14\.
